# AI Matching Design (3-Level Photo Matching & Grouping System)

## Goal

Organize photos uploaded to a shared room into useful person collections and organized galleries using an anonymous 3-level visual face clustering and categorization pipeline. The AI groups visually similar faces without requiring face registration, selfie enrollment, or account-linked biometric identities.

---

## Terms

- **Face detection:** Locates human faces within an uploaded photo and extracts bounding coordinates.
- **Face embedding:** Numeric vector (e.g. 512-d) generated by a deep learning model representing facial features for visual similarity comparison.
- **Anonymous person collection (Cluster):** A group of visually similar face instances clustered together automatically within a room (e.g. "Person 1", "Person 2").
- **Cluster naming:** User-assigned human-readable label for an anonymous collection (e.g., naming "Person 1" as "Rafiqul" or "Samira"). The AI never infers real-world identities on its own.
- **Level 2 Close match suggestion:** A candidate similarity between a detected face/photo and a candidate person cluster when the AI is plausible but uncertain.
- **Level 3 Rest Photos:** The categorized repository for photos that cannot be confidently assigned to known people or contain no recognizable human faces.

---

## The Three-Level Matching Architecture

```
                                 [ Uploaded Photo ]
                                         │
                                         ▼
                            [ Face Detection & Extraction ]
                                         │
                 ┌───────────────────────┼───────────────────────┐
                 ▼                       ▼                       ▼
       [ High Confidence ]      [ Marginal / Close ]      [ Unassigned / Rest ]
        (Cosine >= T_high)      (T_low <= Cosine < T_high)  (No Face / Low Conf / Error)
                 │                       │                       │
                 ▼                       ▼                       ▼
        LEVEL 1: CONFIDENT        LEVEL 2: SUGGESTIONS     LEVEL 3: REST PHOTOS
        • Auto-assign to Person   • Do NOT auto-assign     • Categorized storage:
        • Group photos: 1 photo   • Review Suggestions UI     1. Unknown Faces
          in multiple people        with top candidates       2. No People (Scenic/Food)
          collections             • User confirms "Is B"      3. Other Unassigned
        • Original stored ONCE    • Resolve A, Assign B    • Manual tagging support
                                  • Reject / Undo support
```

### Level 1 — High Confidence (Automatic Matching)
- **Automatic Association:** When visual similarity meets or exceeds the calibrated high-confidence threshold (`similarity >= T_high`), the detected face is automatically assigned to that known person cluster.
- **Multi-Person Group Photos:**
  - If multiple known people appear in a single photo (e.g., Alice, Bob, and Charlie in one group shot), the **exact same photo reference** is added to every matched person's collection.
  - **Single Storage Rule:** The original photo file is stored **only once** in the configured storage system (e.g., Cloudflare R2). Person collections are represented via database foreign keys (`photo_assignments`), never by duplicating files.
- **Cluster Creation:** If a high-confidence face appears that does not match any existing person cluster in the room, a new anonymous person collection (e.g., "Person 5") is automatically initialized.
- **Non-Destructive:** All automatic assignments record provenance metadata and can be reviewed, renamed, or manually moved by authorized room members at any time.

### Level 2 — Close Match Suggestions (Human-in-the-Loop Review)
- **Plausible but Uncertain:** When a face match falls in the marginal band (`T_low <= similarity < T_high`), the AI **must never confirm the match automatically**.
- **Review Suggestions Section:**
  - Photos with uncertain matches appear in a dedicated **Review Suggestions** area.
  - The UI presents the photo alongside only the closest candidate people (e.g., "Candidate 1: Rafiqul [74%]", "Candidate 2: Tanvir [68%]").
- **Explicit Identification & Correction (A → B):**
  - An authorized room member can explicitly identify the correct person. For example, if the AI suggested Person A, but the user identifies the face as Person B:
    1. The system resolves and removes the pending suggestion for Person A.
    2. The system creates a confirmed assignment to Person B.
- **Group Photo Support in Level 2:**
  - If a group photo has multiple uncertain faces, each face can be confirmed independently for different people.
- **Rejection & Non-Assumption Rule:**
  - Users can reject a suggestion with one click.
  - **Critical Rule:** Never treat a rejection of Person A as proof that Person B is the match. Rejecting a suggestion simply marks that candidate rejected; it does not trigger automatic fallback assignment.
- **Undo Capability:**
  - Users can undo mistakes or accidental rejections. All correction actions record previous state in an audit log to support immediate rollback.
- **Model Stability Rule:**
  - Individual user corrections **do not retrain, fine-tune, or modify the underlying machine learning model weights**. Corrections only update room-scoped database assignment records.

### Level 3 — Unsorted / Rest Photos (Categorized Fallback)
Photos that cannot be confidently assigned to known people or contain no recognizable human faces are organized in the **Rest Photos** section with three distinct, useful filters:

1. **Unknown Faces (People Detected but Not Identified):**
   - Photos containing human faces that were successfully detected, but either had confidence below `T_low` or did not match any existing room collection.
   - **Crucial Rule:** Never classify an unknown human face as a non-person photo!
   - Authorized room members can browse these photos and manually tag faces to an existing or new person collection.
2. **No People (Scenery, Nature, Objects):**
   - Photos with zero detected human faces: sunsets, ocean waves, mountain landscapes, buildings, monuments, food, and wildlife.
   - Cleanly separated so users browsing scenery never see accidental people, and users searching for friends never wade through sunsets.
3. **Other Unassigned (Exceptions & Processing Issues):**
   - Photos with severe motion blur, extreme low-light/underexposure, extreme occlusions, or temporary processing exceptions.
   - Allows users to review failed or edge-case media and manually categorize them.

## Core Data & Storage Architecture Rules

1. **Single Physical Storage:** Every original photo is uploaded and stored exactly once in private object storage (Cloudflare R2).
2. **Many-to-Many Relational Representation:** 
   - A single photo can be associated with 0, 1, or 10+ people collections using the `public.photo_assignments` relational table.
3. **AI Suggestion vs Confirmed Assignment Separation:**
   - Pending AI suggestions live in `public.uncertain_matches` with status `pending_review`.
   - Confirmed associations live in `public.photo_assignments` with `assignment_level` (`confident`, `confirmed_suggestion`, `manual`).
4. **Correction History & Auditability:**
   - All manual taggings, suggestion confirmations, corrections (A → B), and rejections are logged in `public.assignment_history` with `(media_id, previous_person, new_person, action, actor_id, timestamp)` to power undo actions.
5. **Strict Room Authorization:**
   - Room membership and authorization must be verified before viewing, correcting, downloading, or deleting any photo or suggestion. Cross-room access is strictly blocked via PostgreSQL Row-Level Security (RLS).
6. **No Biometric Account Linking:**
   - Embeddings and clusters are strictly scoped to the room. No global facial profiles are ever created or linked to user accounts.

## Threshold Calibration & Operational Workflow

| Level | Condition | Action | Storage Impact |
| :--- | :--- | :--- | :--- |
| **Level 1** | Similarity $\ge T_{\text{high}}$ (e.g. $\ge 0.82$) | Auto-assigned to person collection(s) | 1 file stored; relational links created |
| **Level 2** | $T_{\text{low}} \le \text{Similarity} < T_{\text{high}}$ (e.g. $0.65 – 0.81$) | Sent to Review Suggestions with top candidates | Stored in Rest until user confirms / corrects |
| **Level 3 (Unknown Faces)** | Faces detected, Similarity $< T_{\text{low}}$ | Placed in Rest Photos $\rightarrow$ *Unknown Faces* | 1 file stored; face bounding boxes saved |
| **Level 3 (No People)** | 0 faces detected | Placed in Rest Photos $\rightarrow$ *No People* | 1 file stored; tagged as non-person scenery |
| **Level 3 (Other)** | Blur / occlusion / processing failure | Placed in Rest Photos $\rightarrow$ *Other Unassigned* | 1 file stored; flagged for manual review |
